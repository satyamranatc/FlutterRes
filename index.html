Chapter 1

Introduction to Flutter

By the end: you can explain what Flutter and Dart are, when to use them, and how you will work day to day.

What is Flutter?

Flutter is a free toolkit from Google for building apps. With one codebase you can make apps for Android, iOS, web, Windows, macOS and Linux.

Think of it like a set of LEGO bricks. Instead of carving every shape from scratch, you snap together ready-made pieces (called widgets) to build your screens.

What is Dart?

Dart is the programming language you write Flutter apps in. It is also made by Google. If you have seen Java, JavaScript, C# or Kotlin, Dart will feel familiar.

Dart
void main() {
  String name = 'Asha';
  int age = 20;
  print('Hello, $name. You are $age years old.');
}

In plain English

  • main() is where every Dart program starts.
  • String holds text, int holds whole numbers.
  • $name drops a variable's value into a string.

Why use Flutter?

ONE CODEBASE

Write once

One project targets many platforms, so you do less duplicate work.

FAST

Hot reload

Change code, save, and see the result in under a second without restarting.

CONSISTENT

Your own pixels

Flutter draws every pixel itself, so your app looks the same on every device.

COMMUNITY

Packages

Thousands of free packages on pub.dev add features like maps and payments.

Advantages and limitations

Advantages

Single codebase · quick development · beautiful, custom UIs · strong performance · great documentation.

Limitations

Apps are a bit larger than minimal native apps · you learn Dart · some brand-new platform features arrive later · web is better for apps than for content sites.

What can Flutter build?

  • Mobile apps: shopping, learning, fitness, social and banking apps.
  • Web apps: dashboards and admin tools (not ideal for blogs or SEO-heavy sites).
  • Desktop apps: tools for Windows, macOS and Linux.
  • Embedded and kiosk screens: in-car displays, smart screens.

Chapter 2

Understanding the App Architecture

By the end: you know what each part of a real app does and how data flows between them.

A real app is more than screens. Picture a restaurant: the Flutter app is the dining room and menu, the API is the waiter, the backend is the kitchen, and the database is the pantry.

Flutter appScreens, buttons,
what the user sees
requestJSON
Backend APIRules, logins,
business logic
queryrows
DatabaseUsers, courses,
saved data
Your Flutter app should talk to the backend. The backend talks to the database.

The parts, one by one

FRONTEND

Flutter app

Runs on the user's device. Shows UI and collects input.

BACKEND

Server

A program on a computer in the cloud. Applies rules and protects data.

STORAGE

Database

Stores information permanently: users, courses, orders.

BRIDGE

API

A list of addresses (URLs) the app can call to get or change data.

IDENTITY

Authentication

Proves who the user is, usually with email and password, then a token.

GO LIVE

Hosting

Where your backend runs online. The app goes to Play Store or App Store.

Example: a student app

Imagine an app that lists courses and remembers who is logged in.

  1. The student enters email and password in the Flutter app.
  2. The app sends them to POST /login on the backend.
  3. The backend checks the database and replies with a token.
  4. The app asks GET /courses with that token.
  5. The backend fetches courses from the database and returns JSON.
  6. Flutter turns the JSON into a list on screen.
Remember

You can start learning Flutter with no backend at all. Chapters 3 to 9 use only local data. We add APIs in Chapter 10.

Chapter 3

Flutter Widgets and Their Types

By the end: you recognise the most important widgets and know when to reach for each.

What is a widget?

In Flutter, everything on screen is a widget: text, buttons, padding, even the app itself. Widgets are nested inside other widgets to form a widget tree.

MaterialApp
 └─ Scaffold
    ├─ AppBar → Text("Home")
    └─ Padding
       └─ Column
          ├─ Text("Hello")
          └─ ElevatedButton
A widget tree. Parents contain children.

StatelessWidget vs StatefulWidget

STATELESS

Never changes

Draws the same thing for the same input. Example: a title, an icon, a logo.

STATEFUL

Can change

Holds data that changes over time. Example: a counter, a checkbox, a form.

Dart
import 'package:flutter/material.dart';

class Greeting extends StatelessWidget {
  const Greeting({super.key, required this.name});

  final String name;

  @override
  Widget build(BuildContext context) {
    return Text('Hello, $name!');
  }
}

Every widget has a build method that returns what it looks like. We cover stateful widgets fully in Chapter 6.

Essential widgets reference

Each entry has a purpose, a tiny example, and when to use it.

MaterialApp

Purpose: The root of most apps. Sets the theme, title, home screen and routes.

Dart
MaterialApp(
  title: 'My App',
  theme: ThemeData(colorSchemeSeed: Colors.blue),
  home: const HomePage(),
)

Use it: once, at the top of your app.

Scaffold

Purpose: The basic page structure: app bar, body, drawer, bottom bar, floating button.

Dart
Scaffold(
  appBar: AppBar(title: const Text('Home')),
  body: const Center(child: Text('Welcome')),
)

Use it: as the root of nearly every screen.

Container and SizedBox

Purpose: Container is a flexible box with size, color, padding and decoration. SizedBox is a lightweight box for fixed sizes or empty gaps.

Dart
Container(
  width: 120,
  height: 60,
  padding: const EdgeInsets.all(8),
  decoration: BoxDecoration(
    color: Colors.blue.shade50,
    borderRadius: BorderRadius.circular(12),
  ),
  child: const Text('Box'),
)

const SizedBox(height: 16)   // a 16-pixel vertical gap

Use it: Container when you need decoration; SizedBox for spacing.

Text and Image

Purpose: Show words and pictures.

Dart
const Text(
  'Learn Flutter',
  style: TextStyle(fontSize: 24, fontWeight: FontWeight.bold),

Image.network(
  'https://picsum.photos/200',
  width: 100,
  height: 100,
  fit: BoxFit.cover,
)

Use it: Image.asset for pictures bundled in your app, Image.network for pictures from the internet.

Icon and Buttons

Purpose: Icons add meaning. Buttons respond to taps through onPressed.

Dart
const Icon(Icons.favorite, color: Colors.red, size: 28)

ElevatedButton(
  onPressed: () => print('Saved'),
  child: const Text('Save'),
)

TextButton(onPressed: () {}, child: const Text('Cancel'))
IconButton(onPressed: () {}, icon: const Icon(Icons.share))

Use it: ElevatedButton for the main action, TextButton for secondary ones, IconButton in toolbars. A button with onPressed: null is disabled.

TextField

Purpose: Lets the user type. Full coverage in Chapter 9.

Dart
const TextField(
  decoration: InputDecoration(
    labelText: 'Your name',
    border: OutlineInputBorder(),
  ),
)

Use it: any time you need free text input.

Row, Column, Center, Padding

Purpose: Row lays children side by side, Column stacks them vertically, Center centers one child, Padding adds space around a child.

Dart
Padding(
  padding: const EdgeInsets.all(16),
  child: Column(
    children: const [
      Text('First'),
      SizedBox(height: 8),
      Text('Second'),
    ],
  ),
)

Use it: these are the backbone of almost every layout. See Chapter 4.

Expanded and Flexible

Purpose: Inside a Row or Column, they decide how children share leftover space.

Dart
Row(
  children: [
    const Icon(Icons.school),
    const SizedBox(width: 8),
    Expanded(child: Text('A very long course title that wraps nicely')),
  ],
)

Use it: Expanded to fill all remaining space; Flexible when the child may be smaller.

Stack and Positioned

Purpose: Stack widgets on top of each other, like papers on a desk.

Dart
Stack(
  children: [
    Image.network('https://picsum.photos/300/160'),

      bottom: 8,
      left: 8,
      child: Text('Caption', style: TextStyle(color: Colors.white)),
    ),
  ],
)

Use it: badges on images, text over pictures, floating labels.

ListView and GridView

Purpose: Scrollable lists and grids.

Dart
ListView.builder(
  itemCount: courses.length,
  itemBuilder: (context, index) {
    return ListTile(title: Text(courses[index]));
  },
)

GridView.count(
  crossAxisCount: 2,
  children: const [Text('A'), Text('B'), Text('C'), Text('D')],
)

Use it: ListView.builder builds only items on screen, so it is great for long lists.

Card and ListTile

Purpose: Card is a raised, rounded panel. ListTile is a ready-made row with icon, title and subtitle.

Dart

Use it: for list items, settings rows, and course entries.

Purpose: The top bar, the slide-out side menu, and the bottom tabs. All are slots on a Scaffold.

Dart
Scaffold(

Chapter 4

Layout Basics

By the end: you can arrange widgets confidently and style boxes using Flutter's own tools.

Not like CSS

Flutter has no CSS. Backgrounds, borders, rounded corners and shadows are set with a BoxDecoration. Expanded and Flexible are widgets you wrap around a child, not properties like flex: 1 in CSS.

Row and Column

A Row lines things up left to right. A Column stacks them top to bottom. Think of a shelf: a row is one shelf, a column is the whole bookcase.

Row
A
B
C
Column
A
B
C
Row = horizontal. Column = vertical.

Center and alignment

Every Row and Column has a main axis (the direction it lays out) and a cross axis (the other direction). You control both:

Dart
Row(
  mainAxisAlignment: MainAxisAlignment.spaceBetween, // along the row
  crossAxisAlignment: CrossAxisAlignment.center,     // up and down
  children: const [
    Text('Left'),
    Text('Right'),
  ],
)
MainAxisAlignmentResult
startPack children at the start
centerPack children in the middle
spaceBetweenFirst and last touch the edges; equal gaps between
spaceEvenlyEqual space everywhere, including the edges

Width and height

Use SizedBox or Container to give a size. Prefer flexible sizing (Expanded, constraints) over fixed numbers where you can. Chapter 13 explains why.

Dart
SizedBox(
  width: double.infinity, // as wide as the parent allows
  height: 48,
  child: ElevatedButton(onPressed: () {}, child: const Text('Continue')),
)

Padding and margin

Padding is the space inside a box, like the cushioning in a gift box. Margin is the space outside, like the gap between two boxes on a shelf.

Dart
Container(
  margin: const EdgeInsets.all(16),                 // outside
  padding: const EdgeInsets.symmetric(              // inside
    horizontal: 20,
    vertical: 12,
  ),
  color: Colors.blue.shade50,
  child: const Text('Cozy box'),
)

Other options: EdgeInsets.only(left: 8), EdgeInsets.fromLTRB(8, 4, 8, 4).

Colors, borders, radius and shadows

All of these live in one place: BoxDecoration.

Dart
Container(
  padding: const EdgeInsets.all(16),
  decoration: BoxDecoration(
    color: Colors.white,                                  // background
    border: Border.all(color: Colors.grey.shade300),     // border
    borderRadius: BorderRadius.circular(12),             // rounded corners
    boxShadow: const [
      BoxShadow(
        color: Colors.black12,
        blurRadius: 8,
        offset: Offset(0, 2),                            // shadow position
      ),
    ],
  ),
  child: const Text('A styled box'),
)
Common trap

If you set color on the Container and a decoration, Flutter throws an error. When using decoration, put the color inside it.

Elevation is the Material way to show height. Widgets like Card and ElevatedButton have an elevation property that draws a shadow for you:

Dart
Card(
  elevation: 2,
  shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(12)),
  child: const Padding(padding: EdgeInsets.all(16), child: Text('Raised')),
)

Constraints and responsive sizing

Flutter's golden rule: constraints go down, sizes go up, parent sets position. A parent tells a child "you may be between this and this wide". The child picks a size in that range and reports back.

Dart
// Limit content width on big screens
Center(
  child: ConstrainedBox(
    constraints: const BoxConstraints(maxWidth: 600),
    child: const Text('Readable on tablets and phones'),
  ),
)

// React to the available space
LayoutBuilder(
  builder: (context, constraints) {
    final isWide = constraints.maxWidth > 700;
    return isWide ? const Text('Wide layout') : const Text('Narrow layout');
  },
)

// Or read the screen size
final width = MediaQuery.of(context).size.width;

Expanded, Flexible and Flex

Imagine a pizza shared among friends. Expanded says "I take whatever slice is left". The flex number says how many parts each friend gets.

Row
Icon
Expanded (flex: 2)
Expanded (flex: 1)
Fixed icon first, then leftover space split 2 : 1.
Dart
Row(
  children: [
    const Icon(Icons.star),
    Expanded(flex: 2, child: Container(height: 40, color: Colors.blue)),
    Expanded(flex: 1, child: Container(height: 40, color: Colors.lightBlue)),
  ],
)
  • Expanded forces the child to fill its share.
  • Flexible lets the child take up to its share but be smaller (fit: FlexFit.loose).
  • Flex is the parent class of Row and Column. You rarely use it directly.

Images, aspect ratios and fit

Dart
ClipRRect(
  borderRadius: BorderRadius.circular(12),
  child: AspectRatio(
    aspectRatio: 16 / 9,
    child: Image.network(
      'https://picsum.photos/640/360',
      fit: BoxFit.cover,
    ),
  ),
)
BoxFitWhat it does
coverFills the box, crops the extra (most common)
containShows the whole image, may leave empty space
fillStretches to fit (can distort)

Spacing and visual hierarchy

Make the most important thing the biggest or boldest. Group related items closely and leave larger gaps between groups. Pick a spacing scale (such as 8, 16, 24, 32) and stick to it.

Chapter 6

Understanding StatefulWidget

By the end: you can build screens that react to taps and typing.

What is state?

State is data that can change while the app runs. A counter number, whether a switch is on, the text a user typed: all state. A lamp is a good analogy: the lamp is the widget, and "on or off" is its state.

How the UI updates

User actiontaps a button
→
State changeinside setState()
→
Rebuildbuild() runs again
→
New UIscreen shows new data
Change state inside setState(), and Flutter redraws for you.

Example 1: a counter

Dart
class CounterPage extends StatefulWidget {
  const CounterPage({super.key});

  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
  int _count = 0;

  void _increment() {
    setState(() {
      _count++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Counter')),
      body: Center(
        child: Text('Tapped $_count times',
            style: Theme.of(context).textTheme.headlineMedium),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _increment,
        child: const Icon(Icons.add),
      ),
    );
  }
}

In plain English

  • A stateful widget is two classes: the widget, and a State class that holds the data.
  • _count is the state. The underscore makes it private to this file.
  • setState(() { ... }) changes the data and tells Flutter "please rebuild".
  • Without setState, the number changes in memory but the screen stays the same.

Example 2: show or hide content

Dart
class _DetailsState extends State<Details> {
  bool _showMore = false;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        const Text('Flutter is a UI toolkit.'),
        if (_showMore)
          const Text('It uses Dart and draws its own widgets.'),
        TextButton(
          onPressed: () => setState(() => _showMore = !_showMore),
          child: Text(_showMore ? 'Show less' : 'Show more'),
        ),
      ],
    );
  }
}

The if inside a list adds the widget only when the condition is true. The ! flips true to false and back.

Example 3: handling simple input

Dart
class _GreeterState extends State<Greeter> {
  String _name = '';

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          decoration: const InputDecoration(labelText: 'Your name'),
          onChanged: (value) => setState(() => _name = value),
        ),
        const SizedBox(height: 12),
        Text(_name.isEmpty ? 'Type your name above' : 'Hello, $_name!'),
      ],
    );
  }
}

onChanged runs on every keystroke, so the greeting updates as you type.

Rule of thumb

Keep setState small and call it only when something visible changes. Do slow work (like network calls) outside it, then call setState with the result.

Chapter 7

Navigation and Multiple Screens

By the end: your app has Home, Courses and Profile screens, with data passed between them.

In Flutter, screens are called routes. The Navigator keeps them in a stack like a pile of cards: push puts a new screen on top, pop removes it and reveals the previous one.

Homebottom of stack
push →
Courseson top
push →
Course Detailvisible now
Back button or Navigator.pop() removes the top screen.

Basic push and pop

Dart
// Go to a new screen
Navigator.push(
  context,
  MaterialPageRoute(builder: (context) => const CoursesScreen()),
);

// Go back
Navigator.pop(context);

Named routes

Named routes give each screen a short address. Register them once in MaterialApp:

Dart
MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (context) => const MainShell(),
    '/detail': (context) => const CourseDetailScreen(),
  },
)

// Elsewhere:
Navigator.pushNamed(context, '/detail', arguments: 'Flutter Basics');

Passing data between screens

Two simple ways. The easiest is a constructor parameter:

Dart
class CourseDetailScreen extends StatelessWidget {
  const CourseDetailScreen({super.key});

  @override
  Widget build(BuildContext context) {
    // Read what was sent through "arguments"
    final title = ModalRoute.of(context)!.settings.arguments as String;

    return Scaffold(
      appBar: AppBar(title: Text(title)), // back arrow appears automatically
      body: Center(child: Text('Details for $title')),
    );
  }
}

The second option is to send data back when popping: Navigator.pop(context, 'result'), and read it with final result = await Navigator.push(...).

Forms and User Input

By the end: you can build a validated login and registration form.

TextField vs TextFormField

TextField is a simple input. TextFormField is the same thing but works inside a Form, so it supports validation. Use TextFormField when you have a form.

Controllers

A TextEditingController lets you read, set or clear the text. Always dispose it to free memory.

Dart
final _nameController = TextEditingController();

@override
void dispose() {
  _nameController.dispose();
  super.dispose();
}

// Later:
final text = _nameController.text;
_nameController.clear();

Forms and validation

A GlobalKey<FormState> lets you ask the whole form "is everything valid?". A validator returns an error message, or null if the value is fine.

Dart
class LoginForm extends StatefulWidget {
  const LoginForm({super.key});

  @override
  State<LoginForm> createState() => _LoginFormState();
}

class _LoginFormState extends State<LoginForm> {
  final _formKey = GlobalKey<FormState>();
  final _email = TextEditingController();
  final _password = TextEditingController();
  bool _hidePassword = true;

  @override
  void dispose() {
    _email.dispose();
    _password.dispose();
    super.dispose();
  }

  void _submit() {
    if (_formKey.currentState!.validate()) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Logging in...')),
      );
    }
  }

  @override
  Widget build(BuildContext context) {
    return Form(
      key: _formKey,
      child: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            TextFormField(
              controller: _email,
              keyboardType: TextInputType.emailAddress,
              decoration: const InputDecoration(
                labelText: 'Email',
                border: OutlineInputBorder(),
              ),
              validator: (value) {
                if (value == null || value.isEmpty) return 'Please enter your email';
                if (!value.contains('@')) return 'That does not look like an email';
                return null; // null means valid
              },
            ),
            const SizedBox(height: 16),
            TextFormField(
              controller: _password,
              obscureText: _hidePassword,
              decoration: InputDecoration(
                labelText: 'Password',
                border: const OutlineInputBorder(),
                suffixIcon: IconButton(
                  tooltip: 'Show or hide password',
                  icon: Icon(_hidePassword ? Icons.visibility : Icons.visibility_off),
                  onPressed: () => setState(() => _hidePassword = !_hidePassword),
                ),
              ),
              validator: (value) =>
                  (value == null || value.length < 6) ? 'Use at least 6 characters' : null,
            ),
            const SizedBox(height: 24),
            SizedBox(
              width: double.infinity,
              height: 48,
              child: FilledButton(onPressed: _submit, child: const Text('Log in')),
            ),
          ],
        ),
      ),
    );
  }
}

In plain English

  • validate() runs every validator and shows red messages under failing fields.
  • obscureText hides characters for passwords.
  • SnackBar is a small message shown at the bottom.

Chapter 10

APIs and Backend Integration

By the end: you can fetch JSON from an API and show loading, success and error states.

What is an API?

An API (Application Programming Interface) is a menu of requests your app can make to a server. You ask politely at a URL; the server answers with data.

HTTP requests

MethodMeaningExample
GETRead dataGET /courses
POSTCreate new dataPOST /courses
PUTUpdate existing dataPUT /courses/3
DELETERemove dataDELETE /courses/3

Responses come with a status code: 200 OK, 201 created, 400 bad request, 401 not logged in, 404 not found, 500 server error.

JSON

JSON is a text format for data, made of key-value pairs and lists. APIs usually speak JSON.

JSON
{
  "id": 1,
  "title": "Flutter Basics",
  "lessons": 12
}

In Dart, jsonDecode turns that text into a Map (or a List of Maps), which you convert into your own class.

Fetching and showing API data

First, add the http package:

Terminal
flutter pub add http
Permissions

On Android, add <uses-permission android:name="android.permission.INTERNET"/> to android/app/src/main/AndroidManifest.xml for release builds. On macOS, enable the "outgoing network" entitlement.

We will use JSONPlaceholder, a free fake API that returns sample posts.

Dart
import 'dart:convert';

import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;

class Post {
  final int id;
  final String title;
  final String body;

  const Post({required this.id, required this.title, required this.body});

  factory Post.fromJson(Map<String, dynamic> json) {
    return Post(
      id: json['id'] as int,
      title: json['title'] as String,
      body: json['body'] as String,
    );
  }
}

Future<List<Post>> fetchPosts() async {
  final response = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/posts?_limit=10'),
  );

  if (response.statusCode == 200) {
    final List<dynamic> data = jsonDecode(response.body);
    return data.map((item) => Post.fromJson(item)).toList();
  } else {
    throw Exception('Server error: ${response.statusCode}');
  }
}

In plain English

  • Post is a Dart class that mirrors one JSON object.
  • fromJson converts a Map into a Post.
  • Future means "the answer arrives later". await waits for it without freezing the UI.
  • We check statusCode and throw an error if it is not 200.

Loading, success and error states

FutureBuilder rebuilds the UI as the future moves from waiting to done:

Dart
class PostsPage extends StatefulWidget {
  const PostsPage({super.key});

  @override
  State<PostsPage> createState() => _PostsPageState();
}

class _PostsPageState extends State<PostsPage> {
  late Future<List<Post>> _future;

  @override
  void initState() {
    super.initState();
    _future = fetchPosts(); // start once, not on every rebuild
  }

  void _retry() {
    setState(() {
      _future = fetchPosts();
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Posts')),
      body: FutureBuilder<List<Post>>(
        future: _future,
        builder: (context, snapshot) {
          if (snapshot.connectionState == ConnectionState.waiting) {
            return const Center(child: CircularProgressIndicator());
          }
          if (snapshot.hasError) {
            return Center(
              child: Column(
                mainAxisSize: MainAxisSize.min,
                children: [
                  const Text('Something went wrong.'),
                  TextButton(onPressed: _retry, child: const Text('Try again')),
                ],
              ),
            );
          }
          final posts = snapshot.data ?? [];
          if (posts.isEmpty) {
            return const Center(child: Text('No posts found.'));
          }
          return ListView.builder(
            itemCount: posts.length,
            itemBuilder: (context, index) {
              final post = posts[index];
              return ListTile(
                title: Text(post.title, maxLines: 1, overflow: TextOverflow.ellipsis),
                subtitle: Text(post.body, maxLines: 2, overflow: TextOverflow.ellipsis),
              );
            },
          );
        },
      ),
    );
  }
}
Mistake to avoid

Do not call fetchPosts() directly inside build. It would re-send the request every time the screen rebuilds. Store the future in initState.

Sending data: POST

Dart
Future<void> createPost(String title, String body) async {
  final response = await http.post(
    Uri.parse('https://jsonplaceholder.typicode.com/posts'),
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({'title': title, 'body': body, 'userId': 1}),
  );

  if (response.statusCode != 201) {
    throw Exception('Could not create post');
  }
}

PUT and DELETE work the same way with http.put and http.delete.

Basic authentication concepts

  1. The user sends email and password to POST /login.
  2. The server checks them and returns a token (like a wristband at a concert).
  3. The app sends the token with later requests.
  4. The server verifies the token before returning private data.
Dart
final response = await http.get(
  Uri.parse('https://api.example.com/me'),
  headers: {'Authorization': 'Bearer $token'},
);
Storing tokens

Save tokens with a secure storage package such as flutter_secure_storage, not in plain text files. Always use HTTPS.

Never put secrets in a client app

Very important

Anything inside your Flutter app can be extracted by someone determined: strings, API keys, database passwords. Never put a database username, password, or admin secret key in app code. Anyone who gets them could read or delete all your data.

The backend is the guard at the door. The database is never exposed to the internet directly.

This is why a backend API is often needed: it checks who is asking and what they may do. Firebase is an exception, because it is designed to be called from apps. It stays safe through security rules and Authentication. Its config values are identifiers, not secrets.

Example: saving student course information

The database table:

SQL
CREATE TABLE enrollments (
  id          SERIAL PRIMARY KEY,
  student_id  INT NOT NULL,
  course_name TEXT NOT NULL,
  enrolled_at TIMESTAMP DEFAULT NOW()
);

A tiny backend endpoint that saves an enrollment (Node.js with Express; this is not Flutter):

Node.js
app.post('/enroll', requireLogin, async (req, res) => {
  const { courseName } = req.body;
  await db.query(
    'INSERT INTO enrollments (student_id, course_name) VALUES ($1, $2)',
    [req.user.id, courseName]   // user id comes from the verified token
  );
  res.status(201).json({ message: 'Enrolled!' });
});

And the Flutter side that calls it:

Dart
Future<void> enroll(String courseName, String token) async {
  final response = await http.post(
    Uri.parse('https://api.example.com/enroll'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $token',
    },
    body: jsonEncode({'courseName': courseName}),
  );
  if (response.statusCode != 201) {
    throw Exception('Enrollment failed');
  }
}

Notice the app never touches the database. It only knows the API address and the user's token.

Chapter 12

State Management and Reusable Code

By the end: you know how to share data between widgets and what to learn next.

Local widget state

What you used in Chapter 6. State lives inside one widget. Perfect for things only that widget cares about: a toggle, a text field, a selected tab.

Lifting state up

If two widgets need the same data, move the state to their closest common parent. The parent passes the value down, and passes a function down so children can ask for changes.

Parent (owns state)int count
DisplayWidgetreceives count
ButtonWidgetreceives onTap callback
Data flows down. Events flow up.
Dart
class ParentPage extends StatefulWidget {
  const ParentPage({super.key});

  @override
  State<ParentPage> createState() => _ParentPageState();
}

class _ParentPageState extends State<ParentPage> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        CountDisplay(count: _count),
        AddButton(onTap: () => setState(() => _count++)),
      ],
    );
  }
}

class CountDisplay extends StatelessWidget {
  const CountDisplay({super.key, required this.count});
  final int count;

  @override
  Widget build(BuildContext context) => Text('Count: $count');
}

class AddButton extends StatelessWidget {
  const AddButton({super.key, required this.onTap});
  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) =>
      ElevatedButton(onPressed: onTap, child: const Text('Add'));
}

Passing data through constructors

You already did it above. Constructor parameters (required this.count) are the simplest and clearest way to share data downward. Prefer them until the chain gets very deep.

Reusable custom widgets

Extract repeated UI into small widgets with clear parameters, as with CourseCard in Chapter 8. Small widgets are easier to read, test and reuse. Mark them const where possible for better performance.

Provider and Riverpod: next steps

When passing data through many layers becomes painful, use a state management package. Both let any widget read shared state without passing it through every constructor.

BEGINNER FRIENDLY

Provider

Simple and widely used. Wraps a ChangeNotifier and rebuilds listeners when it changes.

MODERN

Riverpod

From the same author as Provider. More flexible and safer, with less reliance on the widget tree.

A taste of Provider:

Dart
class CounterModel extends ChangeNotifier {
  int count = 0;

  void increment() {
    count++;
    notifyListeners(); // tells listening widgets to rebuild
  }
}

// In main():
runApp(
  ChangeNotifierProvider(
    create: (_) => CounterModel(),
    child: const MyApp(),
  ),
);

// In any widget:
final count = context.watch<CounterModel>().count;
context.read<CounterModel>().increment();
Don't rush

You do not need these until your app has several screens sharing data. Master setState and constructors first.

Chapter 13

Common Beginner Mistakes

By the end: you can spot and avoid the nine mistakes almost every beginner makes.

1. Putting everything in one widget

A 600-line build method is hard to read. Fix: extract sections into small widgets like ProfileHeader and CourseList.

2. Fixed widths and heights everywhere

A width: 400 overflows on a small phone and looks tiny on a tablet.

Dart
// Fragile
Container(width: 400, child: Text('Hello'))

// Flexible
Row(children: [Expanded(child: Text('Hello'))])

See a yellow-black striped "overflow" warning? That is usually this. Use Expanded, Flexible, ListView or SingleChildScrollView.

3. Forgetting setState()

Dart
// Wrong: value changes, screen does not
onPressed: () { _count++; }

// Right
onPressed: () { setState(() { _count++; }); }

4. Deeply nested layouts without structure

Ten levels of brackets are painful. Fix: pull parts into methods or, better, separate widgets. Your editor's "Extract Widget" refactor does it in one click.

5. Ignoring loading and error states

Networks fail. Always handle waiting, error, empty and success (Chapter 8 and 10).

6. Repeating code

Copy-pasting the same card five times means five places to fix later. Make one reusable widget.

7. Poor spacing and inconsistent colors

Define colors in ThemeData and use a spacing scale. Do not scatter Color(0xFF123456) across the code.

8. Exposing API keys or database credentials

Security

Never commit secrets to GitHub or put them in app code. Keep them on a backend, and use environment variables there.

9. Not testing on different screen sizes

Test a small phone, a large phone, a tablet, landscape mode, and with large system fonts. Flutter DevTools and your emulator's device list make this easy.
